# 项目实际预期与开发约束

这份文档记录项目的实际目标，作为后续研究、实现和评审的范围基准。它优先描述逆向工作中真正有用的证据，不把分析过程本身当成产品目标。

## 项目定位

`auto-refirst` 是一个面向逆向预处理的工具。它需要比普通格式识别、通用脱壳工具做得更深：发现壳和运行时释放内容后，尽量得到后续分析真正需要的程序或区域，并标出会影响逆向判断的隐藏逻辑、反分析行为和运行时变化。

它不是万能的全链路还原器，也不是把所有可能的静态信息都塞进报告的格式百科。每个能力都应围绕一个实际问题：分析者下一步是否能据此定位、验证、脱壳、提取或绕过一个障碍。

## 优先级

### 正确性

正确性指报告事实和实际行为一致，尤其包括：

- 识别、脱壳、释放文件、模块加载和首次执行之间的关系不能混淆；
- 静态推断、运行时观察、物化文件和独立验证必须分开表达；
- 只有证据闭合时才使用较高置信度，不能因为导入、字符串或单条指令出现就断言行为已经发生；
- 能定位时给出文件偏移、RVA、虚拟地址、进程/线程和范围，避免只给模糊标签；
- 失败、拒绝、未执行和未能验证也要准确说明实际阶段，不能把“发现能力”写成“已经发生”。

递归本身不是主要问题。正常输入通常是单个 EXE、ELF、APK 等，递归和预算应服务于真实嵌套内容与运行时子工件，不应为了覆盖极端深度而让普通分析变得臃肿。

### 已有能力的深化

深化应优先解决真实样本中会导致误判或无法继续分析的地方，例如：

- 多层壳逐层脱壳，直到最后一个可分析程序；
- 脱壳后程序的 TLS、初始化、异常处理、调试信息承载、运行一次自修改、隐藏入口和特殊反调试；
- 调试器、虚拟机、硬件断点、异常分发、时间、环境和自校验等组合行为，而不是只枚举 API；
- 运行时释放的文件、DLL、匿名/文件支持的可执行映射、句柄生命周期、线程和子进程之间的 provenance；
- 物化内容的独立再解析、入口和执行范围验证，以及对失败原因的准确保留。

深化不是把每个结构都展开到极限。只有能帮助定位隐藏逻辑、判断脱壳结果或决定下一步操作的细节才进入默认结果；其余细节放在可展开的附加信息中，或留在内部证据模型。

### 能力拓展

能力拓展的目标是解决更多实际输入和保护方式，包括新的文件类型、容器/嵌套关系、壳、释放方式、加载器和反分析手法。拓展时应优先选择：

- 现实中出现频率高、现有工具处理不好的格式或壳；
- 能通过结构和行为证据可靠确认的能力；
- 能产出可保存、可复查、可继续静态分析的工件；
- 有清楚的正例、相似负例、扰动样本和资源边界。

为了拓展而增加的模块不应复制整条流程。脱壳、单文件分析、运行时物化和报告组合可以分成边界清楚的能力块，再由上层按需调用；模块数量要保持适中，避免过度拆分和互相传递难以解释的状态。

## 脱壳与分析边界

发现有壳就应尝试脱壳，支持连续的多层壳；每一层都保留输入、输出和验证关系。最终没有壳、或已经得到可分析主体的程序，再进入深入的单文件检查。

脱壳和程序分析可以分开呈现并相互调用：报告先说明发现的壳、脱壳结果保存在哪里、结果是否验证成功，再说明脱壳后程序发现的实际隐藏行为。一个简单的 UPX 样本不应被强行套用其他复杂场景的流程或对照项。

单文件检查不止 TLS、初始化和异常目录。根据实际证据，还应关注：

- 调试信息、异常元数据或不常见节区中承载的逻辑；
- 运行一次后改变自身、擦除解密结果、改变后续解题条件的行为；
- 自定义编译器、变形代码、控制流改写和不符合常规编译产物的逻辑；
- 反调试和反分析的指令组合、异常控制流、计时、硬件状态、环境探测、断点/补丁检测、暗桩和触发条件；
- 运行时释放文件、可疑 DLL、内存映射和跨线程/跨进程执行转移。

这些方向需要逐个研究、建立证据闭包和负例，而不是盲目宣布“全链路已覆盖”。

## 运行时释放内容

运行时释放内容的核心是回答“什么内容被创建、从哪里来、何时变成可执行、是否真的执行”。应尽量保留：

- 创建 API/系统调用、创建者进程和线程、句柄和设备/inode 等身份；
- 写入、截断、向量写入、文件搬运、映射权限和句柄关闭；
- 首次执行地址、执行范围、物化文件和对应的来源关系；
- 线程、子进程、exec handoff 和继承关系。

普通预先存在的文件、系统库和没有运行时创建证据的映射，不应仅凭“被映射”就升级为隐藏载荷。无法安全追踪时应保留拒绝或不完整状态，而不是制造确定性结论。

## 报告输出原则

默认报告只输出对逆向有帮助的客观事实：

- 基础格式名称直接给结论即可；不必解释为什么识别成 PE、ELF、APK 等；
- 脱壳成功时说明壳、输出工件和验证结果即可；不必重复识别过程；
- 反调试、自修改、运行时释放和暗桩等行为要给出类型、位置、范围、条件和证据状态；
- 详情应支持展开查看，不需要时保持折叠；
- 文本和 JSON 使用一致的核心事实与坐标，附加证据可以更详细但不能改变结论。

报告避免与事实无关的防御性措辞、免责声明、动机推断和泛泛建议。工具可以在内部保留完整证据，但默认输出要短、清楚、能直接指导下一步逆向工作。

## 研究与合入标准

每个新能力至少应有：

1. 一个来自实际机制的正例；
2. 一个相似但不应命中的负例；
3. 必要时加入指令、布局、线程、路径或编译器形态扰动；
4. 明确的资源上限、拒绝条件和坐标语义；
5. 可重复的测试和文档说明；
6. 与现有报告的去重、置信度和输出范围检查。

研究可以参考前沿样本、保护器、恶意软件和反分析技术，但合入标准始终是证据可复核、误报可控制、结果对逆向有用。不能因为某种手法理论上存在，就把模糊共现直接升级为报告结论。

## 明确避免的方向

- 为了“完整”而扫描和解释所有字段、所有链路和所有递归层级；
- 把预处理识别阶段已经解决、且对做题没有帮助的内容重新塞进报告；
- 用固定流程强行对所有文件做相同深度的处理；
- 以导入、字符串、文件名或单个魔数代替行为证据；
- 把能力存在、静态可达、运行时发生、成功物化和独立验证混成一个状态；
- 让新增模块、字段和诊断信息无限增长，导致核心报告难以阅读。
